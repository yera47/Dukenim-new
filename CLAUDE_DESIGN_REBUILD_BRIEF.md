# Задача для Codex / Claude Code

## Цель владельца

Пересобрать публичный сайт Dukenim и его визуальную идеологию на основе нового дизайн-кода: сделать продукт заметно более цельным, удобным и премиальным, с уровнем polish, который ощущается как работа сильной продуктовой команды Apple. Сайт должен оставаться рабочим commerce-продуктом, а не превращаться в декоративный лендинг.

## Что считать результатом

- Новая визуальная система описана в коде: tokens, типографика, сетка, радиусы, поверхности, интерактивные состояния, motion и responsive-поведение.
- Главная объясняет ценность Dukenim через каталог и самостоятельный заказ клиента, а не через абстрактный «ИИ-сервис».
- Страницы `/login`, `/register`, `/admin`, `/root`, `/s/[slug]`, checkout и AI Studio сохраняют существующую бизнес-логику, роли, RLS и доступность.
- Новый дизайн последователен на desktop и мобильной ширине 390×844; reduced-motion и клавиатурная навигация не ломаются.
- Любые изменения тарифов, пробного периода, платежей, заказов, склада, OAuth и AI API запрещены, если они не нужны для визуальной интеграции.

## Направление дизайна

- Сохранить утверждённые Black Jade `#071B17`, Aged Gold `#B08A50`, Pale Stone `#F4F0E8`, Graphite `#101713`, Warm Sand `#E8DFD0` и Manrope.
- Уйти от шаблонного «обычного AI SaaS»: меньше декоративных градиентов и одинаковых карточек, больше ясной иерархии, редакционного ритма, спокойных поверхностей и физически понятных состояний.
- Motion использовать только для объяснения перехода/результата; уважать `prefers-reduced-motion`.
- Не копировать Apple и не использовать чужие логотипы/тексты; перенять только качество композиции, ясность и внимание к деталям.

## Этапы

1. Провести аудит текущих маршрутов и собрать карту повторяющихся компонентов и визуальных долгов.
2. Предложить один главный visual direction и кратко обосновать его через брендбук и продуктовую идеологию.
3. Обновить foundations/tokens и shared UI без массового переписывания бизнес-логики.
4. Пересобрать главную: hero, proof, workflow «каталог → заказ → управление», тарифы, AI Studio/support choice и footer.
5. Перенести систему на auth, admin, root и storefront только там, где это улучшает единообразие.
6. Добавить визуальные regression/smoke проверки и пройти TypeScript, tests и production build.
7. Обновить `AI_HANDOFF.md` с фактическими изменениями, проверками и остаточными рисками. Не объявлять сайт «10/10» без проверки критических потоков.

## Ограничения и критерии приёмки

- Не хранить секреты, ключи, платёжные данные или персональные данные в brief, Git или shared context.
- Не менять production OAuth, Polar, Supabase schema, тарифы или внешние аккаунты в рамках первой дизайн-серии.
- Не удалять существующие маршруты и не подменять рабочие формы статическими макетами.
- Перед каждым крупным изменением зафиксировать screenshots/визуальные наблюдения; после — проверить desktop и 390×844.
- Обязательные проверки перед handoff: `npx tsc --noEmit`, `npm test`, `npm run build`.

## Следующее действие Claude Code

Начать с read-only аудита и вернуть короткий план из найденных visual debt, затрагиваемых файлов и одного рекомендуемого направления. После этого реализовать направление поэтапно, сохраняя рабочее состояние после каждого этапа.
