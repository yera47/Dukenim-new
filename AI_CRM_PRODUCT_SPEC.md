# Dukenim — AI Studio и CRM-интеграции

Статус: продуктовая спецификация для реализации. Это не означает, что внешние CRM, Azure или онлайн-оплата уже подключены.

## 1. Коммерческая модель

| Тариф | Месяц | Год | Для кого | Ключевая ценность |
|---|---:|---:|---|---|
| Старт | 24 900 ₸ | 239 000 ₸ | Магазин, которому нужна готовая витрина, заказы и склад | Каталог, заказ без переписки, CRM Dukenim |
| Бренд | 34 900 ₸ | 335 000 ₸ | Магазин, которому важны собственная подача и ускоренная сборка | Всё из «Старт», домен, бренд-настройки, акции и AI Studio |

Год оплачивается одной суммой. Экономия: 59 800 ₸ для «Старт» и 83 800 ₸ для «Бренд» — примерно два месяца, без выдуманной процентной скидки. На публичной странице показаны обе суммы, переключатель периода меняет цену без перехода и одновременно меняет подпись об экономии. По умолчанию — помесячная цена: это снижает барьер первого решения. Годовая — вторична, но всегда видима и выделяет выгоду.

### Почему 24 900 / 34 900

- Маркетинг: 24 900 читается ближе к «до 25 тысяч», 34 900 — «до 35 тысяч». Разница не скрыта: клиент понимает, что доплачивает 10 000 ₸ за отдельный рабочий слой, а не за абстрактное слово «премиум».
- Продажи: «Старт» продаётся как стоимость одного потерянного заказа/нескольких часов ручной переписки; «Бренд» — как экономия времени на запуске акций, наполнении и обновлении витрины. Нельзя обещать выручку без подтверждённых данных.
- Продукт: «Бренд» обязан давать измеримое действие, а не только декоративный дизайн: AI-сессии, собственный домен, бренд-настройки, кампании и аналитика.

## 2. AI Studio — безопасная модель

У клиента всегда два понятных пути:

1. **Выбрать шаблон** — доступно на обоих тарифах: шаблон, готовая палитра и ручная настройка.
2. **Собрать с ИИ** — только «Бренд»: структурированный бриф, три направления, preview и ручное подтверждение.

AI Studio не создаёт произвольный исходный код, SQL, права доступа или новый сайт из непроверенного текста. Он создаёт версионированный черновик темы из разрешённой схемы Dukenim:

```text
brief → AI gateway → проверка JSON-схемы → draft theme
→ desktop/mobile preview → владелец применяет → опубликованная тема
```

### Первый состав AI Studio

- Бриф: ниша, название, логотип, желаемая подача, палитра, первый товар/фото.
- Три варианта только из поддерживаемых шаблонов и блоков: `Atelier`, `Journal`, `Gallery`.
- Помощник для названия, описания товара, категории, SEO-черновика и текста акции.
- Preview до применения, версия/откат, журнал: кто и когда применил изменения.
- Базовый лимит для «Бренд»: **5 AI-сессий темы в месяц**. Один сеанс возвращает до трёх направлений и один уточняющий прогон. Лимит должен быть серверным, видимым клиенту и настраиваемым Root; не завязывать его на предполагаемую стоимость кредитов в интерфейсе.

### Azure-архитектура

- Azure Foundry/Azure OpenAI используется только сервером через ключ в секретном хранилище; ключ никогда не приходит в браузер.
- Next.js route/worker создаёт задание; очередь и idempotency-key защищают от двойных запусков.
- `ai_requests`: tenant, тип задачи, входные параметры без секретов, модель, token/cost estimate, результат, статус, время и версия шаблона.
- Лимиты: на tenant/день, tenant/месяц, платформу/день, platform/месяц; hard-stop при неуспешной Azure-квоте.
- Fallback: вместо списания без контроля показываем «AI Studio временно недоступна; используйте шаблон или сохраните черновик». Никакой деградации заказа, CRM и витрины.
- Root видит потребление, ошибки, очередь, лимиты и может отключить конкретному tenant AI без удаления магазина.

Azure-кредиты — субсидия инфраструктуры, а не обещание клиенту «бесплатного безлимитного ИИ». После их окончания сохраняются тарифные лимиты; решение о self-funded стоимости принимается по фактической телеметрии и валовой марже.

## 3. CRM-интеграции: как продукт, а не поле для ключа

### Место в пути клиента

CRM нельзя прятать в оплате и нельзя требовать при регистрации. После создания каталога на dashboard показывается большой action-card:

```text
Подключите рабочую систему
Синхронизируйте заказы и клиентов с CRM, которой уже пользуетесь.
[Выбрать CRM]   [Добавить позже]
```

Основной экран: `/admin/integrations`. В подписке и в persistent header показывается компактный статус: тариф + `CRM: не выбрана / нужен доступ / на проверке / подключена / требуется внимание`. На `/root/integrations` — операционная очередь, а не копия клиентского экрана.

### Состояния заявки

`not_selected → details_later → credentials_needed → submitted → preflight → waiting_owner → connected | failed | revoked`.

«Добавить позже» сохраняет `details_later` и не блокирует каталог, заказы или подписку. Поля доступа открываются только для выбранного провайдера. Клиент может вернуться в любой момент. В `submitted` он видит иллюстрацию ожидания, что именно проверяется и дату последнего обновления; Root получает запись в очереди.

### Поддерживаемость

| Провайдер / группа | Первый способ | Кто даёт доступ | Решение для запуска |
|---|---|---|---|
| Bitrix24 | OAuth для масштабного приложения; inbound webhook для одной учётной записи | Пользователь с API-доступом; для полного доступа нужен администратор и верные scopes | Tier 1: поддержать первым, OAuth — целевой путь |
| Kommo / amoCRM | OAuth 2.0 | Установить интеграцию может администратор; токены выдаются после согласия | Tier 1: поддержать первым, не просить пароль/скрин ключа |
| МойСклад | API token / OAuth-подобный доступ в зависимости от сценария | Владелец или администратор учётной записи | Tier 1 после отдельного preflight API и складского mapping |
| retailCRM | API key/права зависят от аккаунта и подключённых модулей | Обычно администратор | Tier 2: заявка + preflight, не обещать self-serve до проверки |
| 1С:Предприятие | Web/HTTP services, OData или кастомный обмен | Администратор базы и часто интегратор 1С | Tier 3: assisted only, отдельная оценка mapping и сети |
| Kaspi/маркетплейсы, POS и отраслевые CRM | Условия/партнёрский API различаются | Часто merchant/партнёр или интегратор | Каталог заявок, без публичного обещания готовой синхронизации |

Доступ и набор методов всегда проверяются до включения. Bitrix24 прямо ограничивает webhook scope и правами создавшего его пользователя; Kommo требует OAuth/интеграцию и администратор устанавливает её. Секреты не показываются Root в открытом виде и не попадают в логи, email, браузер или экспорт.

### Поля формы

Общие: провайдер, URL/поддомен аккаунта, контакт администратора, желаемое направление синхронизации, комментарий.

- OAuth-провайдер: кнопка «Подключить через …» и callback; не ручной ввод client secret.
- Webhook/token: только защищённое server-side поле, scope checklist, тест соединения и срок действия.
- 1С/кастом: тип обмена, контакт интегратора, staging URL при наличии; credentials позднее через защищённую форму.

## 4. Цена и акция CRM

Стандартный assisted-коннектор: ориентир **70 000 ₸** разово. Это не единая цена для любой CRM.

Расчёт: 10–12 часов на discovery, field mapping, OAuth/webhook, тесты, мониторинг и handoff × ориентир 5 000 ₸/час = 50–60k; плюс риск поддержки/инфраструктуры ≈10–20k. Кастомная 1С или закрытый API получают отдельную оценку до начала работ.

На старте показывается: `70 000 ₸` зачёркнуто → `0 ₸` и «Бесплатно для первых подключений в честь запуска Dukenim». Рядом всегда есть условия: заявка проходит технический preflight; закрытый или кастомный API может потребовать отдельного согласования. Это не манипуляция и не обещание невозможной интеграции.

## 5. Root: операционная очередь

Таблица `/root/integrations`:

- магазин, владелец, тариф, billing period, AI usage;
- CRM, направление синхронизации, статус, ответственный, SLA/последнее изменение;
- preflight result, missing fields, безопасная ссылка на vault reference (не сам секрет);
- действие: назначить себя, запросить данные, подтвердить, отключить, открыть журнал.

Фильтры: новые, просроченные, credentials needed, provider, тариф, ответственный. Любое изменение статуса создаёт immutable audit event. Клиент получает realtime-обновление через Supabase Realtime с polling fallback.

## 6. Очерёдность реализации

1. Единый источник новых цен и Monthly/Annual UX.
2. Схема integration requests, RLS, encrypted secret references, Root queue и клиентские статусы.
3. Bitrix24/Kommo OAuth proof-of-concept в тестовой среде; затем один реальный preflight.
4. Azure Foundry resource, Key Vault, budget alerts, AI request ledger и schema validator.
5. AI Studio UI и preview; только после server-side budget gate.
6. Cinematic media: отдельные короткие видео для hero/AI Studio/CRM, только после доступа к подходящей модели Higgsfield или другому согласованному генератору.

## 7. Критерии готовности

- Переключатель цены меняет сумму, годовую экономию, URL регистрации и a11y state.
- Все AI результаты — draft, tenant-isolated, versioned и проверены схемой.
- Ни Azure key, ни CRM token/webhook URL не доступны клиентскому JavaScript, Root UI или логам.
- Клиент может закончить регистрацию и продавать без CRM/AI.
- Ни один CRM connector не маркируется «подключён» до test call и mapping verification.
