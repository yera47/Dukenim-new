## Зависимости, которые исключают простое массовое удаление

Удаление магазина каскадно удалит связанные заказы, каталог, движения склада, программу лояльности и переписку. `platform_audit_events.tenant_id` станет `NULL`. Для удаления Auth-пользователей отдельные внешние ключи `buyer_members`, `buyer_order_access`, `buyer_referrals` и `loyalty_redemptions` используют `RESTRICT` (сейчас эти четыре таблицы пусты); `staff_invitations.created_by` использует `NO ACTION` (одно приглашение существует). У десяти Storage-объектов указан владелец из удаляемых аккаунтов; Auth API может отказать в удалении пользователя, пока его файлы существуют.

## Стоп-условия сейчас

Поэтому шаги удаления не запускались. После входа владельца в Dashboard нужно проверить backup/restore и выполнить экспорт с проверкой до мутаций.

## Отдельные требования, которые очистка не решает

Удаление Auth-аккаунта или запрет нового входа не отзывает уже выпущенный JWT немедленно. Для глобального отзыва нужен отдельный согласованный механизм серверных действий, RLS и функций. Ручная отметка Kaspi и возврата не переводит деньги. Живые CRM, эквайринг и возвраты требуют полномочий провайдеров; физический телефон нужен для полевых измерений. SMS отложен владельцем.
