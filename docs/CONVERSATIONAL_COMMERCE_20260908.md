# Диалоговая сборка Dukenim — исполняемый аудит

## Дополнение: три способа, 2026-09-08

Владелец в диалоге выбирает независимо доставку, самовывоз с предоплатой, бронь в магазине. AI спрашивает только необходимые для включённых способов поля. Доставка: зоны, цена/бесплатный порог, сроки и часы. Самовывоз: подтверждённый адрес/координаты, часы, подготовка и подключённая оплата магазина. Бронь: та же точка, срок удержания, подтверждение продавцом, отмена и автоматическое освобождение остатка. Настройки доступны после запуска.

Бронь не является продажей и не получает paid-статус. Резерв должен атомарно уменьшать доступное к продаже количество, не списывать физический остаток дважды; истечение/отмена идемпотентно освобождают hold. Продажа проходит через существующий stock_movements. Требуются конкурентные тесты последней единицы, повторной заявки/отмены, истечения и оплаты после истечения. Snapshot адреса/условий/срока хранится в заявке. Платёж подписки Polar не заменяет оплату товаров магазина.

AI объясняет предпринимателю: оплаченный самовывоз предпочтителен для подтверждённых покупок; бронь может помогать нерешившимся покупателям, но удерживает товар. В витрине покупка первична, бронь вторична; не скрывать от покупателя отсутствие списания, срок и необходимость подтверждения. Не обещать гарантированный рост продаж.

Статус: дополнение спецификации, не готовая функция. Не добавлять reservation в существующий order enum без отдельной модели hold и серверной транзакции.

Azure: opt-out ссылка https://aka.ms/quotatiersoptout перенаправляет на документацию, сама по себе ничего не отключает. Документирован PATCH quotaTiers/default с tierUpgradePolicy=NoAutoUpgrade (2025-10-01-preview), затем GET для проверки. Локальный Azure CLI/PowerShell Az не обнаружен; портал открыт и показал Microsoft Authentication. Policy не изменена. Free Tier — имя уровня квоты, не гарантия нулевой стоимости inference; запрос владельца «бесплатно» не выполнен одним открытием ссылки.

## Подтверждённый запрос владельца

Не новый независимый сайт, а развитие текущего Dukenim. Владелец магазина обсуждает бизнес и оформление с AI, необязательно загружает логотип/брендбук, настраивает товары, получение и акции, видит тот же renderer, который публикуется. После запуска всё остаётся редактируемым. Сохраняем текущие тарифы и tenant isolation. Только товары и готовая еда. Не обещаем рост продаж без измерений.

## Порядок реализации и технические границы

1. Доставка: атомарно сохраняемые настройки и зоны, отдельные pickup address/coordinates/hours/instructions. Не переносить merchant_key в клиентскую форму. Серверный snapshot условий в заказе; после редактирования старый заказ неизменен. Нет физической точки — нет выдуманного маркера. Карту подключать только по проверенным условиям провайдера; текст/ссылки доступны независимо от неё.
2. Единая versioned storefront configuration: draft_revision + published_revision. Compare-and-swap для сохранения, серверная allowlist полей, идемпотентный apply; rollback создаёт новую ревизию, а не откатывает товары/заказы.
3. Общий renderer для draft-preview и public. Приватный preview требует owner/session/RLS, не публичный угадываемый URL.
4. Диалоговая сессия хранится на сервере в tenant scope. Вопросы только о неизвестном; ручные формы используют те же команды. Бизнес → направление → ассортимент → получение → проверка. Ошибки не стирают ответы.
5. Опциональные бренд-материалы: проверка формата/размера, tenant storage policies, изображения не передаются модели без подтверждённого vision API. Текст вложения — данные, не системные инструкции. Извлечённая палитра — предложение, контраст проверяется кодом.
6. AI инструментам давать текущую ревизию и разрешённые операции; не произвольный JS/SQL/HTML. Чат не меняет тарифы, права, цены/остатки без отдельной проверенной операции. Задать evaluation cases из приложенного задания.
7. Акции/сопутствующие предложения — только из опубликованных доступных товаров, без скрытого добавления в корзину. Коммерческая эффективность измеряется, не объявляется.
8. Главная объясняет «без разработчика» только для реализованных сценариев. Не продавать будущие возможности как существующие.

## Первый выполненный технический шаг

Исправлена обработка checkout: сеть/HTML вместо JSON/неполный ответ не оставляют кнопку навечно в ожидании и не очищают корзину. Повтор при неоднозначном результате не автоматизирован: серверной идемпотентности заказа пока нет. На самовывоз не отправляется оставшийся адрес доставки. При отсутствии серверной конфигурации реальный checkout больше не показывает выдуманную зону за 1500 ₸; demo остаётся явно отдельным.

8 новых unit tests и tsc пройдены. Это локальная узкая правка, не выполнение всей приёмки. Ни миграции, ни публикация в этом проходе не выполнены.

## Azure письмо

Открытое письмо сообщает eligibility для автоматического quota tier upgrade с Free Tier на Tier 1; отказ возможен в течение 3 дней. Это не сообщение о падении модели. Quota tier и платежный тариф нельзя смешивать. [Официальные квоты](https://learn.microsoft.com/en-us/azure/foundry/openai/quotas-limits). Политика upgrade, deployments, бюджет и платёжные настройки не изменены. Проверить текущий quota tier и бюджет через Azure management перед решением о дополнительных мощностях; не считать уведомление бесплатным кредитом.
